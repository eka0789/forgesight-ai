# Datasets — ForgeSight AI

## 1. AI4I 2020 Predictive Maintenance (schema mirror)

- **Reference**: UCI ML Repository — "AI4I 2020 Predictive Maintenance Dataset"
  (Matzka, 2020), 10,000 rows, 5 sensor channels + failure modes.
- **This repo**: `ml/datasets/ai4i_synthetic.csv` — a **synthetic mirror**
  generated by `ml/training/generate_ai4i_synthetic.py` (deterministic seed 42)
  implementing the *documented generator thresholds* of the original dataset:
  - TWF: tool wear ∈ [200, 240] min
  - HDF: (process − air temp) < 8.6 K AND rotational speed < 1380 rpm
  - PWF: power (torque × angular speed) ∉ [3500, 9000] W
  - OSF: tool_wear × torque > 11,000 minNm
  - RNF: 0.1% random
- **Why synthetic?** Reproducible offline training/CI without a dataset
  download step; exact schema/column semantics match the original so the real
  CSV drops in unchanged.
- **Using the real dataset**: place `ai4i_real.csv` (UCI column names like
  `Air temperature [K]`) in `ml/datasets/` — training scripts auto-detect,
  alias columns, and set `is_synthetic: false` in artifacts metadata.
- **Measured profile** (synthetic): 10,000 rows, failure rate 0.1795
  (modes: TWF 1094, HDF 241, PWF 498, OSF 166, RNF 17).

### Limitations
- Failure rate (~18%) is higher than the real dataset (~3.4%) → the class
  imbalance story is milder; class weighting is still applied and reported.
- No tool-quality (`Type` L/M/H) column — inference payloads don't carry it.
- Sensor distributions are Gaussian approximations, not measured physical
  sensor noise.

## 2. C-MAPSS-style RUL trajectories (synthetic)

- **Reference**: NASA C-MAPSS turbofan run-to-failure datasets (schematically).
- **This repo**: `ml/datasets/cmapps_synthetic_rul.csv` — 260 units ×
  variable-length cycles (60,750 rows) with load-dependent degradation of ΔT,
  vibration, wear. RUL = remaining cycles (≈ hours at 1 cycle/h).
- **Real C-MAPSS**: drop `cmapps_real.csv` with columns
  `unit, cycle, <sensors…>, rul` and adapt `load_or_generate` (documented).
- **Measured**: test MAE ≈ 12.7 cycles, R² ≈ 0.87 (RF vs HistGB compared).

### Limitations
- Degradation is a smooth stochastic function — real turbofan degradation has
  regime changes and sensor faults; RUL uncertainty intervals are not modeled.

## 3. Vision — procedural defect surfaces (synthetic)

- `app/services/vision/synth.py` generates 224×224 BGR "metal" textures with
  classes **clean / scratch / stain / dent** (documented synthetic).
- CNN split: 480 train + 120 test per class (deterministic seeds, disjoint
  seed ranges between splits to avoid leakage).
- **Real datasets scaffolded**: NEU Surface Defect Database and MVTec AD are
  supported conceptually (folder-of-images + loader adaptation); no download
  is bundled. The trained CNN must be considered a *pipeline demonstrator*
  until trained on real factory imagery.

## 4. Demo documents

`app/seed.py` ships 3 small industrial documents (CNC SOP, quality manual,
maintenance policy) that are genuinely ingested through the real pipeline
(extraction → chunking → embeddings) at seed time. Marked `is_demo`.

## 5. Data governance

- All uploaded files stored under opaque keys; organization-scoped access.
- Tenant isolation enforced at query level and covered by tests.
- Uploaded document content is treated as **untrusted input** (sanitization +
  delimiting in RAG).
